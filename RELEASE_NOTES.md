* Terminology Subsystem: a lang-pack or extension-codes supplement is only used without being referenced when it has codesystem-supplement-global = true. This replaces the global-lang-pack handling in the last release - a supplement marked global-lang-pack, or a lang-pack without codesystem-supplement-global, is now only used when it is referenced
* Terminology Subsystem: reserved code spaces (codesystem-reservedCodeSpace) - a code that matches one is a valid code of the code system, with the display an extension-codes supplement gives it (a global one first), else the code space's default-display ('User-assigned' if none). It is a member of a value set that includes all of the code system or lists the code (filters never select one); an expansion of all of a code system that reserves code spaces is marked unclosed
* Terminology Subsystem: supplements - a supplement's display is added as a designation in the supplement's language; nested concepts are merged once; when several versions of a supplement are in scope, only the one asked for by version (else the latest) applies
* Terminology Subsystem: `concept` / `code` `in` and `not-in` value set filters are supported
* Terminology Subsystem: a listed code excluded because it is inactive is reported as not in the value set; a value set with an unknown modifier extension on an include, exclude or filter can't be expanded (an error naming the extension); inferring the system of a code when the value set includes an unknown code system is an error; an unknown code system version is reported instead of crashing
* Validator: Profiles now enforce the invariants of the element a contentReference points to (e.g. cmp-1, cmp-2 and cmp-3 on Composition.section.section), as validation against the base resource always did, so IGs with document profiles may see new errors on their examples
* Validator: CodeSystem supplements - nested concepts are checked against the base code system; a warning when a supplement has no language (its displays and designations with no language count as correct in all languages); in an extension-codes supplement, warnings for a code outside the base code system's reserved code spaces, and for hierarchy among codes from a reserved code space
* Validator: Snapshot generation - expanding a contentReference keeps the referenced element's invariants (see above)
* Validator: a StructureMap import with no value, a dependent call to a group input with no mode, and a ValueSet expansion parameter or valueset-parameter extension with no name are reported instead of crashing
