* QA: link checking: a link to a file the publisher adds at the root of the IG when it's published (full-ig.zip, qa.html, qa-tx.html, qa-ipreview.html, the history page) is checked against where the page it's in is. From a page in a language folder (en/), full-ig.zip without ../ is now reported as a broken link, as it is in the published IG (#1494)
* QA: link checking: links to the IPA and IPS comparisons (ipa-comparison-v{version}/index.html, ips-comparison-v{version}/index.html) are known to the link checker, as the previous version comparisons are - they were reported as broken (#1494)
* Generator: page content can use {{root-path}} to link to files at the root of the IG (package.tgz, full-ig.zip, the comparisons...): it is ../ in a page in a language folder (e.g. en/), and empty otherwise, so {{root-path}}package.tgz works in either. Available in markdown and xml pages, but not in artifact intros and notes, or pages that are complete html (#1494)
* QA: new qa-experimental.html, linked from qa.html: the IG's own resources that are marked experimental, with their name, url, status, and whether they're examples, and whether the ImplementationGuide itself is experimental. The summary in qa.html gives the count
* Generator: status rendering: a resource's standards status, when it's inherited from its parent and the same as the parent's, records the parent it's inherited from (it was recorded on the FMM, and the statuses were compared as objects, so never matched). FMM support is taken from the resource's fmm-support extension, and the standards status has its own support text, from the resource's standards-status-reason extension - it was taken from fmm-support, and replaced the FMM's. 'Inherited from' lists the parents without a leading comma
* Generator: PlantUML diagrams in the folders the new IG parameter path-image-source names (fhir2.base.template sets input/images-source and template/images-source) are rendered to svg in _includes by the publisher, instead of by a plantuml.jar in the template. Files ending .plantuml or .puml are rendered; the images have the names the PlantUML command line gave them. Layout is always PlantUML's own (smetana), so Graphviz isn't needed. A problem in a diagram is an error in qa.html (with the line), and two diagrams that make an image with the same name get a warning. PlantUML runs in its SANDBOX security profile, so it can't read files or fetch anything itself (its standard library still works): the publisher does !include for files in the image source folders. The folders must be inside the IG's folder
* Watch mode: a watched folder (e.g. fsh-generated) that is deleted and made again straight away is watched again as soon as it's made, without waiting for the old watch to be cancelled
* Terminology: a value set that requires a code system supplement (valueset-supplement) is sent to a server that knows the supplement, not one that only knows the code system (a Canadian value set on v3 ActCode that requires the Infoway fr-CA supplement went to tx.fhir.org instead of the Canadian server). A required supplement that isn't loaded, but that the terminology ecosystem knows a server for, sends the validation to that server; one no server has is still reported as missing
* Loader: Windows: [tmp] is no longer c:\temp when c:\temp isn't one of the folders the publisher's file access is limited to (it didn't exist when the limits were set), which gave 'cannot be accessed by policy' errors
* Templates: local runs: a template in a local folder (template = #my-template, or a path such as ../my-template) is trusted by its absolute folder, not by the name the IG gives it, which is a different template in every IG. Trust already given to such a template by its name (e.g. '#template' in trustedTemplates in fhir-settings.json) no longer counts, so you'll be asked once more. -trust-template takes the template as the IG names it, or its folder; either way, the folder is what's recorded. The message when a template isn't trusted names the folder, quoted
* Templates: the reason a template counts as active content lists everything that makes it so (content in scripts/, a registered ant script, and every file extension that isn't on the list of harmless ones), not just the first thing found. .DS_Store files are ignored, a pre-compressed copy (x.css.gz, x.js.br) is judged as the file it's a copy of, and a . in a folder name is no longer taken for a file extension
* Loader: Windows: a path-resource folder/* entry no longer fails the check that the resource folders exist ('*' can't be in a Windows file name)
* Templates: local runs: template overrides in ig.ini (a template's package id = a local folder, for template development) are only used if your fhir-settings.json has "allow-template-overrides": true, which you set by hand; otherwise they're ignored, with a message saying so. A template loaded from an override isn't subject to the active content rules: it's your own
