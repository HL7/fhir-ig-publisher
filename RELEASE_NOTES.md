* Generator: Liquid (r4b, r5, R6): LiquidEngine.setMaxStringLength - the longest string, and the most output, a run can make (default 10 million characters; 0 or less for no limit). The comparison pages (ComparisonRenderer) lift it: their templates are the publication package's, and comparing large value sets (e.g. all of LOINC) makes tables far bigger than 10 million characters, which stopped the comparison

* Generator: Liquid: a template can't nest for, if, capture and include more than 100 deep (LiquidEngine.MAX_DEPTH, counting the levels in included templates), when it's parsed or when it's run - a template that included itself went on until the stack ran out
* Generator: Markdown from HTML (XhtmlToMarkdownConverter): fieldset and legend are left out (they're page controls, e.g. the checkboxes above a profile's mappings table that show and hide its columns) - they were reported as 'Illegal HTML element: fieldset' for every page with them
* Generator: Multi-version packages: a core value set copied into another version's package (e.g. the R4 package of the extensions IG) no longer stays pinned to a source-version code system or value set that isn't copied with it: where the target version's core has it, the pin is changed to the target's version (value-filter-comparator was pinned to search-comparator|5.0.0, which R4 packages don't have)
* Generator: NamingSystem: new NamingSystem-{id}-xref fragment - the value sets that use the code system the NamingSystem identifies. It's always generated (empty unless kind = codesystem) so templates can include it unconditionally (#1187)

* Generator: Narrative in multi-language IGs (LanguageUtils, r5 and R6): when a resource is switched to a language its narrative has nothing for, narrative that was generated (status generated or extensions) is still dropped, to be regenerated in the language. Narrative that was written (additional, empty, or no status) is now kept as it is, in its own language, with a warning - it was dropped, and what was written was lost. Narrative that isn't a resource's own (e.g. Composition.section.text) can't be regenerated, so it's always kept, with a warning (fhir-ig-publisher#1487)
